# 课件知识点总结

## 理解资料

1. 先确定用户要总结的是单份课件、某一章节，还是整门课程。需要时调用 `list_course_materials` 和 `search_course_knowledge`，以实际返回的课件内容为准。不要把文件名相近当作内容相同。
2. 按“前置概念 → 本课主题 → 后续用途”串起相关课件。编译原理示例：第 2 周的文法、推导和语言定义支撑第 3 周的文法分类；第 4 周的正规表达式与 DFA/NFA 连接第 5 周的词法识别实现；第 6 周再转向上下文无关文法的自顶向下分析。只有检索到对应课件时才断言这些联系。
3. 区分定义、判定条件、算法步骤、例题和课堂练习。公式与符号应保留原义。若课件只有结论或图示文字不完整，指出可见部分和缺失部分，不能补写成“课件规定”。
4. 对一个概念至少问清：它解决什么问题、输入是什么、适用条件是什么、输出是什么、与相邻概念如何区别。例：FIRST(α) 与 FOLLOW(A) 的对象不同；判断 LL(1) 要分别检查候选式 FIRST 集冲突和可推出 ε 时与 FOLLOW 集的冲突。

## 生成规范

1. 开头用 2–4 句话说明课件讲了什么，以及这些知识在什么任务中使用。例如正则式用于描述词法规则，有限自动机用于识别单词；LL(1) 条件用于判断是否能无回溯地进行自顶向下分析。
2. 随后按知识链分节列出内容。每节给出“概念/规则 → 适用条件 → 操作方法 → 常见误区”，避免只堆名词或照抄幻灯片标题。
3. 在最需要解释的地方插入小例子。优先引用课件已有例题；若自拟，写明“自拟示例”，并将自拟数据和课件事实分开。例：讲 FIRST/FOLLOW 时用一个很短的文法逐步说明集合如何计算；讲 LL(1) 时展示两个候选式的交集检查。自拟例子需要先自行验算。
4. 引用仅指向实际检索到的原文。不要把自拟例子的符号串或结论伪装为课件引用。单份课件总结不能把别的周次内容写成这份课件的内容；跨课件关联要注明来源。
5. 末尾可用 2–3 个自检问题帮助学生确认理解，例如“ε 何时进入 FIRST 集”“怎样判断两个候选式冲突”，但不能替代正式解释。

## 角色适配

- 学生：先解释概念与步骤，再给可跟算的小例子和易错点。
- 教师：保留正式术语与判定条件，突出先修知识、课堂讲解顺序和可用于检查理解的例题。
