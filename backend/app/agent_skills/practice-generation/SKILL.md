# 生成题目

## 理解资料

1. 先明确目标知识点、题数、题型、难度和使用者。检索指定课件并列出实际覆盖的知识点；若用户要跨周次出题，分别检索相关课件，避免凭文件名推断内容。
2. 把概念题、判定题、计算/推导题和应用题区分开。编译原理示例：文法分类是判定题；给定文法求 FIRST/FOLLOW 是步骤题；判断 LL(1) 需要检查 FIRST/FIRST 及含 ε 候选式的 FIRST/FOLLOW；由正则式画自动机是构造题。
3. 题目只能考已检索到且可验证的内容。可以自拟具体文法或输入串，但要说明是自拟题面，先验证其文法、答案和推导过程。不要把课件练习的题面改几个字就当新题，也不要暴露原课件没有给出的“标准答案”。

## 生成规范

1. 先给出覆盖计划：每个知识点对应几题、题型和难度。题目难度由认知操作决定：识记定义为基础，执行算法或判定条件为中等，综合多个条件、解释反例为较高。
2. 每题应有完整题干、必要的符号约定、唯一可判定的任务、答案和逐步解析。选择题的错误选项要对应真实易错点，不能出现两个都正确、全部明显错误或靠字面长度猜答案的情况。
3. 计算与构造题须验算。求 FIRST/FOLLOW 时检查 ε、开始符号结束标记以及固定点传播；判断 LL(1) 时逐对比较候选式，并在有 ε 时核对 FOLLOW；DFA/NFA 题要核对初态、终态、迁移和被接受的串。
4. 每道题标注来源知识点及依据。自拟的文法、状态图描述或代码片段要标“自拟示例”；来源引用只能对应真实课件片段。资料不足时缩小题目范围并说明缺少哪类依据。
5. 教师要求创建正式练习时，先确认资料 ID、题数、题型与难度齐全；再使用 `generate_practice` 创建。该工具是异步生成，返回后只能说“已创建生成任务”，不能声称题目已经完成。缺参数先询问。学生不能创建正式练习时，可在对话里提供带答案的自测题，不调用写工具。

## 质量检查

提交前逐题检查：题目是否能独立作答、答案是否与解析一致、解析是否用到课件规则、同一套题是否重复考一个细节、难度和题数是否符合要求。若发现歧义，先改题再输出。
